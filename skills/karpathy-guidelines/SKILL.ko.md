# Karpathy 가이드라인 (한국어)

LLM의 흔한 코딩 실수를 줄이기 위한 행동 가이드라인으로, [Andrej Karpathy가 관찰한 LLM 코딩의 함정](https://x.com/karpathy/status/2015883857489522876)에서 도출했습니다.

> 이 문서는 [`SKILL.md`](SKILL.md)의 한국어 번역본입니다.

**트레이드오프:** 이 가이드라인은 속도보다 신중함 쪽으로 치우쳐 있습니다. 사소한 작업에는 판단력을 발휘하세요.

## 1. 코딩 전에 생각하기

**가정하지 말 것. 혼란을 숨기지 말 것. 트레이드오프를 드러낼 것.**

구현하기 전에:
- 가정을 명시적으로 진술하라. 불확실하면 물어라.
- 여러 해석이 존재하면, 제시하라 — 조용히 하나만 고르지 마라.
- 더 단순한 접근법이 있으면 말하라. 타당할 때 반박하라.
- 무언가 불명확하면, 멈춰라. 무엇이 혼란스러운지 짚어라. 물어라.

## 2. 단순함 우선

**문제를 푸는 최소한의 코드. 투기적인 것은 없게.**

- 요청받지 않은 기능은 추가하지 않는다.
- 일회성 코드에 추상화를 두지 않는다.
- 요청받지 않은 "유연성"이나 "구성 가능성"은 넣지 않는다.
- 일어날 수 없는 시나리오에 대한 오류 처리는 하지 않는다.
- 200줄을 작성했는데 50줄이면 될 수 있다면, 다시 작성하라.

스스로에게 물어라: "시니어 엔지니어가 보면 이게 과하게 복잡하다고 할까?" 그렇다면 단순화하라.

## 3. 외과적 변경

**꼭 필요한 것만 건드려라. 네가 어지른 것만 치워라.**

기존 코드를 편집할 때:
- 인접한 코드, 주석, 포맷을 "개선"하지 마라.
- 망가지지 않은 것을 리팩토링하지 마라.
- 다르게 하고 싶더라도 기존 스타일에 맞춰라.
- 무관한 죽은 코드를 발견하면, 삭제하지 말고 언급하라.

변경으로 인해 고아(orphan)가 생기면:
- 네 변경으로 인해 사용되지 않게 된 import/변수/함수를 제거하라.
- 요청받지 않은 한, 기존부터 있던 죽은 코드는 제거하지 마라.

판단 기준: 변경한 모든 줄은 사용자의 요청으로 직접 추적될 수 있어야 한다.

## 4. 목표 주도 실행

**성공 기준을 정의하라. 검증될 때까지 반복하라.**

작업을 검증 가능한 목표로 변환하라:
- "유효성 검사를 추가해" → "잘못된 입력에 대한 테스트를 작성한 뒤, 통과하게 만들어"
- "버그를 고쳐" → "버그를 재현하는 테스트를 작성한 뒤, 통과하게 만들어"
- "X를 리팩토링해" → "리팩토링 전후로 테스트가 통과하는지 확인해"

여러 단계의 작업에는 간단한 계획을 진술하라:
```
1. [단계] → 검증: [확인 항목]
2. [단계] → 검증: [확인 항목]
3. [단계] → 검증: [확인 항목]
```

강한 성공 기준은 독립적으로 반복할 수 있게 해준다. 약한 기준("작동하게 만들어")은 끊임없는 명확화를 요구한다.
